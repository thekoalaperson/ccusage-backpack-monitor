# AGENTS.md — ccusage-backpack-monitor

Guidance for working in this repo, for developers and agents.

## Non-negotiable: no wasteful computation

This tool's core promise is that it costs ~nothing when idle and scales with
*activity*, not wall-clock time. Preserve this in every change:

- The watcher is **change-driven**. When idle it must do nothing but a cheap
  `stat` on the session transcript and its `subagents/` directory (every
  `CBM_POLL` seconds). **Never** introduce a fixed-interval render loop.
- Render **only when something actually changed**.
- **Never shell out to `ccusage` in the render path.** That call rescans every
  transcript on the machine: ~2s wall and ~16 CPU-seconds per turn, which broke
  this promise outright. `lib/usage.py` reads only this session's files.
- Per-file scan results are memoised by `(size, mtime)`. Anything that forces a
  re-read of unchanged files is a regression.
- Account-wide work (the 5h block) must skip files whose mtime falls outside the
  window before opening them.
- Prefer **zero new runtime dependencies** — standard library only, no pip.
  Degrade gracefully rather than erroring.

Before adding a feature, ask: *"does this do work when nothing changed?"* If yes,
redesign it.

## Correctness invariants

These were each a real bug; regressions here are silent and expensive.

- **Never let an unknown model cost $0.** Fall back to a family estimate and mark
  it `~`. Zero looks like "free", which is the failure the user actually hit.
- **Deduplicate per API response.** One assistant reply is written to the
  transcript once per content block, each line repeating the *same cumulative*
  usage. Key on `message.id` (falling back to `requestId`), never on line count.
- **Split cache writes by TTL.** 1-hour writes cost 2x input, 5-minute 1.25x.
- **Attribute subagents to the parent.** They live in
  `<project>/<session-id>/subagents/**/*.jsonl`; the directory name *is* the
  parent link. Some agents run with a different cwd and land in a sibling
  project directory — those are matched on `teamName == session-<sid[:8]>`.
- **One pricing path.** The session total and the 5h figure must be computed the
  same way, or the panel contradicts itself on screen.
- **Never claim a number you inferred.** A percentage against a *guessed* context
  window, or a cost from a guessed rate, must be marked (`~`) or replaced with
  the raw figure. Silent confidence is the failure mode that started all of this.
- **Never floor the render width.** `W` is clamped on the upper bound only; a
  lower floor makes the panel render wider than the pane and wrap. Every row goes
  through `fit()` (drops optional fields) and `clip()` (hard truncation).

Run `python3 tests/test_usage.py` after touching `lib/`.

## No AI-authorship signatures

Never add "made with / generated by Claude / Opus / Sonnet / Claude Code", AI
credits, or `Co-Authored-By: Claude ...` commit trailers to any file, commit
message, or PR body. Referencing Claude Code as the *product this plugin
integrates with* is fine and necessary.

## Layout

- `bin/open-pane.sh`  — SessionStart hook: split a pane, stash backend + pane id
- `bin/watch.sh`      — change-driven loop running inside the pane; the timed
  `read` that waits for a tab key IS the poll interval, never an addition to it
- `lib/render.py`     — pinned header (spend + ctx/5h/week meters) plus six tabs
- `lib/account.py`    — plan, identity and rate limits from Claude Code's own
  caches. Read-only, never fetched, every key guarded (private internals), and
  the age of the cached figure is always reported
- `lib/usage.py`      — transcript scanning, dedup, subagent attribution, 5h block
- `lib/pricing.py`    — model rates: bundled table + daily LiteLLM refresh
- `bin/close-pane.sh` — SessionEnd hook: close that exact pane
- `lib/common.sh`     — shared helpers (python/ccusage detection, PATH, state) plus
  the terminal backends: `cbm_{detect,open,alive,close}_<be>` for herdr, tmux,
  orca, wezterm and iterm, resolved in that order by `cbm_backend`
- `tests/test_usage.py` — fixture-based regression suite
